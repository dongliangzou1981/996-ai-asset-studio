# Codex 已知问题、失败方案和风险

最近更新：2026-06-18。当前文件只记录 996 美术资产生成项目相关风险。

## 生成模式风险

- 不要把参考比例混入普通生成模式。
- 不要把参考图生成和参考图按比例生成混为一类。
- 普通生成不应显示或依赖参考图控件。
- 参考图生成可以上传参考图，但不应带比例参数。
- 参考图按比例生成才允许使用参考比例参数。

## 生产链风险

- 不要破坏三张候选图流程。
- 不要跳过人工确认。
- 不要跳过标记验收。
- 不要假设自动标记一定精准。
- 不要把预览图当正式 996 资源。
- 不要删除 `manifest.json`、`annotation.json`、`candidate_manifest.json`、`delivery_report.json` 等生产记录。
- 不要绕过组件验收直接入库正式资源。

## 透明 PNG 风险

- PNG 文件是 RGBA 不代表真的透明，必须检查 `alpha_min` / `alpha_max` / `has_real_transparency`。
- AI 可能把棋盘格、浅灰底、白底烘焙进图里。
- 透明后处理可能误抠边框或暗色底板，必须看图复核。
- `transparent_guaranteed=true` 只能说明技术 alpha 通过，不能代表美术质量通过。

## 自动标记和切图风险

- 当前自动标记、候选检测、OpenCV 切图仍可能不稳定。
- 如果自动标记和切图不稳定，应记录 PSD 手工补救方案。
- OpenCV fallback 只能作为辅助，不应假定等于最终高质量切图。
- 必须允许用户浏览器手动验收，必要时明确写出用户需要打开哪个页面、看哪个文件。

## AI provider / 环境风险

- 不要编造不存在的 AI provider 能力。
- 不要硬编码 `OFOX_API_KEY`、OpenAI key、OpenRouter key。
- `backend/.env` 可以本机存在，但不得读取或输出 key 内容，不得提交。
- 如果 key 缺失，只记录 AI 不可用，不要强行修复。
- 如果测试命令不存在，记录为环境/脚本问题，不要强行修。

## 项目边界风险

- 不要把知桥 AI 项目内容混入本项目。
- 不要把课程、教师端、学生端、Supabase、Obsidian、iOS 签名等上下文写入本项目文档。

## 当前已知技术债

- 部分历史中文文档存在编码损坏，引用时优先依据代码、测试和仍可读文档，不要复制损坏文本。
- 后端 `ProductionGenerationMode` 与前端三种 UI 生成模式不是同名结构，修改时必须查真实映射。
- `frontend/package.json` 当前没有 `typecheck` script，不要运行或记录成已有命令。
