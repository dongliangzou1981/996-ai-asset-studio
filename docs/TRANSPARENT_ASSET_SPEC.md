# Transparent Asset Spec

## 背景与边界

本文档是 Sprint 9 预研文档，仅定义透明资产的建议规范，不实现透明化处理。

当前 Sprint 8C 已验证输出中，`components/*.png` 是基于模板比例从 `ui_preview` 裁剪出的矩形 PNG。它们可以作为组件切片使用，但尚未保证背景透明、边缘干净、Alpha 规范一致。

## 哪些组件必须透明 PNG

以下组件未来应强制输出透明 PNG：

| 组件类型 | 必须透明的原因 |
| --- | --- |
| 图标 | 需要贴合不同底板、按钮、状态栏背景 |
| 按钮前景 | 需要与按钮底板、按下态、禁用态组合 |
| 独立按钮 | 需要在 996 客户端中复用和重排 |
| 边框 | 需要叠加到不同面板底色上 |
| 输入框边框 | 需要保留中间可填充区域 |
| 装饰角标 | 需要叠加到卡片、头像、奖励图上 |
| 状态徽章 | 需要叠加到头像、资源、任务入口上 |
| 技能槽、道具槽 | 需要在客户端中填充不同图标 |
| 文本装饰底纹 | 需要保留透明外轮廓 |

透明 PNG 的目标是让组件成为可组合资产，而不是整图截图的一块矩形。

## 哪些组件允许整图

以下组件允许保留整图或矩形图：

| 组件类型 | 允许整图的原因 |
| --- | --- |
| `ui_preview` | 用于验收、兜底、坐标参考 |
| 大背景 | 通常就是完整画面或完整层 |
| 固定全屏面板 | 本身覆盖整块区域，透明收益较低 |
| 复杂插画区域 | 自动透明化风险高，人工切分成本高 |
| 临时预览图 | 不作为客户端最终组合资产 |
| `preview.html` 展示截图 | 仅供人工查看，不进入运行时 |

当前 6 个模板组件中，建议优先透明化 `main_bottom_bar`、`skill_area`、按钮、图标和边框类组件。`chat_panel`、`left_status_panel`、`right_menu_panel`、`minimap_area` 可以先允许整图，等识别准确率提升后再拆出透明子组件。

## RGBA 规范

未来透明 PNG 应统一使用 RGBA：

- 文件格式：PNG。
- 色彩模式：RGBA。
- 色彩空间：sRGB。
- 每通道位深：8 bit。
- Alpha 通道必须存在。
- 不使用调色板 PNG 作为最终透明组件。
- 不使用 JPG、WebP 作为 996-ready 透明组件标准格式。

RGBA 语义：

- R/G/B 描述可见颜色。
- A 描述透明度。
- 完全透明像素的 RGB 不作为客户端展示依据。

## Alpha 规范

Alpha 建议分层：

| Alpha 范围 | 语义 |
| --- | --- |
| 0 | 完全透明 |
| 1-31 | 抗锯齿弱边缘或极淡投影 |
| 32-223 | 半透明材质、玻璃、投影、辉光 |
| 224-255 | 主体实色或高不透明区域 |

建议要求：

- 透明组件外接矩形的四角通常应为 Alpha 0，除非组件确实占满角落。
- 不允许把整块背景以 Alpha 255 保留在图标或按钮前景中。
- 组件边缘应保留抗锯齿，不应二值化成生硬锯齿。
- 投影可以保留半透明 Alpha，但需要控制外扩边界。
- 发光效果可以保留半透明 Alpha，但不应导致组件边界过大。

建议在 `annotation.json` 中增加透明相关标注：

```json
{
  "image": {
    "file": "components/main_bottom_bar.png",
    "format": "png",
    "color_mode": "RGBA",
    "alpha": "required",
    "transparent_background": true
  }
}
```

## 图标规范

图标未来应满足：

- 必须透明 PNG。
- 文件名使用 `icon_{name}.png` 或 `{component_id}.png`。
- 图标主体居中，保留少量安全边距。
- 不保留截图中的按钮底板，除非该图标与底板不可分割。
- 单个图标不混入文字标签。
- 不把多个图标拼在一张图里。
- Alpha 外轮廓应干净，避免出现整图裁剪背景。

图标在 annotation 中建议记录：

- `component_type = icon`
- `bounds`
- `anchor`
- `safe_padding`
- `source_parent_id`，如果图标来自按钮或面板内部

## 按钮规范

按钮建议分为两种：

1. 独立按钮：底板、边框、装饰和文字作为一个整体输出。
2. 可组合按钮：底板、边框、图标、文字区域拆分输出。

短期建议：

- 对 Sprint 10，只要求按钮整体透明 PNG。
- 暂不要求九宫格切片。
- 暂不要求按钮状态图自动生成。

按钮透明 PNG 要求：

- 透明背景。
- 保留按钮阴影和发光，但裁剪边界不要过宽。
- 文字如果已经嵌入按钮，应在 annotation 中标明不可编辑。
- 如果文字可编辑，应单独记录字体、字号、颜色和文本区域。

annotation 建议：

```json
{
  "component_type": "button",
  "text_editable": false,
  "states": ["default"],
  "image": {
    "alpha": "required"
  }
}
```

## 边框规范

边框必须透明 PNG。边框资产的核心价值是可叠加到不同面板、弹窗、按钮或输入框上。

建议要求：

- 边框中间区域应透明。
- 四角、描边、发光和阴影保留 Alpha。
- 不把面板底色烘焙进边框，除非该边框不可独立存在。
- 边框外扩区域应有明确 padding，避免客户端摆放时被截断。

短期不建议自动做九宫格参数，但可以在 annotation 中预留：

```json
{
  "component_type": "border",
  "nine_slice": null,
  "center_transparent": true
}
```

## 输入框规范

输入框建议优先拆为：

- 输入框底板。
- 输入框边框。
- 占位文字区域。
- 图标或清除按钮。

短期 Sprint 10 可先只要求：

- 输入框整体透明 PNG。
- annotation 标出文本区域。
- annotation 标出是否可编辑。

输入框要求：

- 背景可半透明，但外部必须透明。
- 文本区域不应与背景图片强绑定。
- 光标、输入文字不应烘焙进最终静态资产。
- 占位文案如果来自生成图，应在 annotation 中标记为示意文本。

建议字段：

```json
{
  "component_type": "input",
  "text_region": {
    "x": 16,
    "y": 8,
    "width": 240,
    "height": 36
  },
  "text_editable": true
}
```

## 当前风险

当前模板裁剪无法判断背景是否属于组件本体，因此存在：

- 图标带背景块。
- 按钮带周围面板。
- 边框中间不透明。
- 输入框文字和底板不可分。
- 投影或发光被裁断。
- 透明通道缺失或退化为 RGB。

短期建议不要把当前 `components/*.png` 直接声明为最终透明资产。应在 manifest 或 annotation 中明确标记：

```json
{
  "transparent_png_required": true,
  "transparent_png_verified": false
}
```

## Sprint 10 建议验收口径

透明 PNG 标准化的首批验收不需要智能识别全部组件，只需要建立可验证基线：

- 输出 PNG 均为 RGBA。
- 必须透明的组件存在 Alpha 通道。
- 图标、按钮、边框、输入框的外部背景不为实色矩形。
- annotation 能标记哪些组件已透明、哪些仍为整图。
- 不破坏 Sprint 8C 的 Ofox E2E 链路。
